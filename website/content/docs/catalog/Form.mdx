## Use it when

A few plain fields need collecting and nothing in the spec has to react to them individually. Both the catalog description and the prompt say to prefer a Stack of Input plus Button for idiomatic binding, and the implementation is why: every field is hard-bound to `/form/<name>` by the component itself, so you cannot choose the path, and the `fields` schema has no `checks`, so per-field validation is out of reach here. Anything that feeds `runTool` should be Inputs.

## Prompt hints

- "Give me a request-access form with name, email and seats"
- "Collect my shipping details"
- "Sign me up for the waitlist"

The submit button fires the element's `submit` event, so the spec attaches actions with `on.submit` the way a Button uses `on.press`; alone, the form does nothing. `submitForm` then snapshots `/form` — falling back to `/ui/form` — into `/lastSubmit`, or into `statePath` if you pass one, as the form values plus an `at` timestamp. `/tools/*` and `/host/*` stay unwritable from a spec either way.

## Props

> Nullable props are optional from the model's point of view: the model must send `null` explicitly, it cannot omit the key.

| Prop | Type | Required | Description |
| --- | --- | --- | --- |
| `title` | `string \| null` | No | Example: `"Request access"` |
| `submitLabel` | `string \| null` | No | Example: `"Submit"` |
| `fields` | `({ label: string; name: string; placeholder: string \| null; inputType: "text" \| "email" \| "number" \| "textarea" \| null })[]` | Yes | Example: `[{"label":"Name","name":"name","placeholder":"Alex","inputType":"text"}]` |

## Example spec

```json title="spec.json"
{
  "type": "Form",

    ]

}
```
