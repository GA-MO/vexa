Vexa is configured in two places and nowhere else. The **server** owns everything that costs money, grants capability, or is prompt text; the **client** owns presentation, formatting, host tools, and page context. The two files below are copy-pasteable and are typechecked with the docs build, so an option that disappears from the library breaks this page first.

`createVexaHandler` returns `GET` (publishes the model list) and `POST` (the chat). Export both from your route.

## Client: the provider

`VexaProvider` wraps the app once; `VexaChatOverlay` (or `VexaChat` inline) reads it. Every `chat` field can also be passed as a prop on the overlay, which wins over the provider.

## What never goes on the client

A tool tier, an approval, a system prompt, a provider key, or a model id the server does not list. The request body is strict and size-capped; anything else is a 400. See [Security](/docs/security).
