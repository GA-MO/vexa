## What it is

`examples/embedded-widget/` is a single-page Vite app for a fictional product, Acme Notes. It has no host tools, no page context, and no API key: `vite/chat-api.ts` mounts `createVexaHandler` on the dev server at `/api/chat` with one model, the scripted mock from `examples/shared/mock-model.ts`. Everything the reader changes on the page is a `VexaProvider` prop.

| File | What it holds |
|---|---|
| `src/app.tsx` | the page: `VexaProvider`, the five guide cards, `VexaChatOverlay` or an inline `VexaChat` |
| `src/guides/presets.ts` | three theme presets, two language presets (English and German labels plus locale and currency), the launcher positions |
| `src/guides/guides.ts` | the guide texts and the snippet builders that print the config currently applied |
| `src/guides/mock-script.ts` | the mock model's replies: a plan-usage card in English and German, and a help list |
| `vite/chat-api.ts` | the Vite plugin that serves the chat route from the dev server |
| `src/app.css` | `@import "tailwindcss"`, `@source` for the library, `@import "vexa/styles.css"`; nothing else, the stylesheet's light defaults do the rest |

## Run it locally

```bash title="terminal"
bun run dev:widget       # http://localhost:3003
```

Every guide card has a control (a select, a checkbox, an input), a prompt button that sends a scripted prompt to the chat, and the code block that reflects the current control values.

## Guides

- **Match the widget to your brand**: `theme` presets (indigo, emerald and rounder, rose on dark) and the `glow` switch that removes the tinted shadows. [Theme](/docs/host/theme)
- **Translate the chat chrome**: `chat.labels` in German for every string down to the composer placeholder, the attach menu, the model picker and the token meter, plus `format` with `de-DE` / `EUR`; the mock replies in German to the German prompt. [Labels and i18n](/docs/host/labels-and-i18n)
- **Trim the composer**: `chat.composer` with `attachments`, `tokenUsage` and `modelPicker` switches; the picker is hidden by itself because the page publishes one model. [Provider](/docs/host/provider#chat-defaults)
- **Place the launcher**: `chat.position`, `chat.launcherLabel`, `backdrop: false`. [Provider](/docs/host/provider)
- **Overlay, framed panel, flush inline, or full page**: swap `VexaChatOverlay` for a `VexaChat` in a fixed-height box, framed or `layout="inline"` (no radius, border, or shadow); `#fullpage` opens `layout="page"` with its centered column. [Provider](/docs/host/provider#where-the-chat-lives)

## What it proved

Building it fixed two library gaps: `vexa/styles.css` now maps every color and radius utility with a light default, so a host with no design tokens renders correctly, and `VexaProvider` keeps stable defaults for `chat`, `functions` and `tools` so a re-rendering host never loops.
