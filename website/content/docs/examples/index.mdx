## Guides, not screenshots

Every example app has a `/guides` page. A guide is one mechanism (the model navigates, a button runs a host tool, an approval is rejected) shown end to end: a **Try it** column with the prompts to send, the chat opening on the right page with the mock model picked, and below it what happens step by step, what the mock replies, the exact tool definitions sliced from the app, and the link to the docs page that explains the mechanism.

The mock model plays a script that lives next to the scenario, so a guide costs nothing and behaves the same every time. Switch the model picker to a real model to see how a prompt steers it; the mock exists to show the chat UI and the runtime, never to judge prompts.

## Run one locally

The real model picker (DeepSeek V4 Flash and the other configured providers next to the mock) needs the dev servers; the hosted builds offer the mock only.

The examples live in the Vexa repository and share the library source, so they need no build step.

```bash title="terminal"
bun install
bun run dev                # shop admin at http://localhost:3001, guides at /guides
bun run dev:widget         # embedded widget at http://localhost:3003
bun run dev:starter-next   # Next.js starter at http://localhost:3004
bun run dev:starter-vite   # Vite starter at http://localhost:3005
```

Each guide links back to its docs page, and the [Shop admin](/docs/examples/shop-admin) and [Embedded widget](/docs/examples/embedded-widget) pages link to every guide; on the published site the links go to the hosted, mock-only builds of both apps.
