## What it is

Vexa Shop admin is the reference host app in `examples/shop-admin/`: an overview at `/`, an orders table at `/orders`, an order page at `/orders/[id]`, `/settings`, and the guides at `/guides`. The chat overlay is mounted once in `examples/shop-admin/components/demo-host.tsx`, which registers the host tools, the page context, and the chat defaults. The route in `examples/shop-admin/app/api/chat/route.ts` is one `createVexaHandler` call with the persona, the rules, the model registry, the server tools and their tiers.

| Layer | Where | What it holds |
|---|---|---|
| Host tools | `examples/shop-admin/lib/shop/host-tools.ts` | `navigate`, `set_filter`, `select_order`, `open_order`, `update_status` (confirm), `set_theme` (confirm), `set_locale`; descriptions and input schemas shared with the guides |
| Page context | `demo-host.tsx` | `path`, `filters`, `selectedOrderId`, `theme`, `locale` |
| Server tools | `examples/shop-admin/lib/shop/server-tools.ts` | `get_orders`, `get_order` (read), `get_supplier_note` (read, carries an injection fixture), `book_room` (write, no approval), `refund_order` (destructive, needs approval) |
| MCP | `examples/shop-admin/scripts/fixture-mcp.ts` | `fixtures__read_file` and `fixtures__write_file` over stdio, on when `VEXA_DEMO_MCP=1` |
| Data | `examples/shop-admin/lib/shop/data.ts` | 24 orders (`C-1019` to `C-1042`) across Bangkok, Chiang Mai, Phuket, and Khon Kaen |

## Run it locally

```bash title="terminal"
bun run dev                      # http://localhost:3001
VEXA_DEMO_MCP=1 bun run dev      # also starts the fixtures MCP server for the mcp-stdio guide
```

Then open [the guides](http://localhost:3001/guides). Every guide page defaults the model picker to **mock**, so nothing below needs an API key; the dev server also lists the models of every provider whose key is in `examples/shop-admin/.env.local` (`QWEN_API_KEY` first, so DeepSeek V4 Flash is the default; see [Models](/docs/server/models)). `bun run test:scenarios` runs the same scenarios headlessly against the real model; add `VEXA_SCENARIO_MODEL=mock` to run them against the script.

## Guides

### Move the user around

- [navigate](http://localhost:3001/guides/navigate): the model changes the route through a host tool, no reload.
- [deep-link](http://localhost:3001/guides/deep-link): one tool call both opens an order and scrolls to a section.
- [page-state](http://localhost:3001/guides/page-state): a tool filters the table and the next turn reads the filter from context.

### Read the page

- [context](http://localhost:3001/guides/context): the model answers from page context alone, no tool call.
- [input-to-model](http://localhost:3001/guides/input-to-model): a typed booking form reaches the model and a server tool with the typed values.

### Let generated UI act

- [button-runtool](http://localhost:3001/guides/button-runtool): a spec button runs a host tool directly, no model round trip.
- [watch-runtool](http://localhost:3001/guides/watch-runtool): a Select change cascades through `watch` into a second Select.
- [server-runtool](http://localhost:3001/guides/server-runtool): a spec button names a server tool; the press is forwarded to the model.
- [form-submit](http://localhost:3001/guides/form-submit): `validateForm` blocks `submitForm` until the form is valid.
- [bound-inputs](http://localhost:3001/guides/bound-inputs): typed values survive a spec patch.
- [patch-after-input](http://localhost:3001/guides/patch-after-input): a follow-up reply patches the existing spec and keeps what was typed.
- [conditional-ui](http://localhost:3001/guides/conditional-ui): `visible`, `repeat` with `pushState`, and a per-row button using `$item`.
- [validation](http://localhost:3001/guides/validation): input checks, a Check button, then a Submit gated on the result.
- [multi-step](http://localhost:3001/guides/multi-step): a two-step wizard built from two Stacks and `/ui/step`.

### Ask before acting

- [approval](http://localhost:3001/guides/approval): a `confirm: true` host tool shows the card; Reject means nothing changed.
- [denial-semantics](http://localhost:3001/guides/denial-semantics): rejecting a destructive server tool twice never triggers a retry loop.
- [host-to-chat](http://localhost:3001/guides/host-to-chat): a button in the app itself asks the chat about an order.

### Bring data

- [server-tools](http://localhost:3001/guides/server-tools): counts and totals come from `get_orders`, never from memory.
- [mcp-stdio](http://localhost:3001/guides/mcp-stdio): a local stdio MCP server with an allow list; the write tool needs approval.

### Stay safe

- [injection](http://localhost:3001/guides/injection): a tool result carrying injected instructions downgrades the turn and shows a notice.

### Look right

- [chat-elements](http://localhost:3001/guides/chat-elements): every chat message part at 340 and 600 px from fixed messages.
- [narrow-panel](http://localhost:3001/guides/narrow-panel): Select, Carousel, and a wide Table at 340 px.
- [theme-format](http://localhost:3001/guides/theme-format): a locale change reflows formatting; a theme change asks for confirmation.
- [keyboard](http://localhost:3001/guides/keyboard): Tab order, Enter-to-submit, and Escape inside the overlay.
