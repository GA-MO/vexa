## Two layers of language

Text in the chat has two sources. Strings the library renders (empty state, thinking indicator, composer placeholder and menus, tool states, approval buttons, security notice) come from `ChatLabels` and are English by default. Text the model writes follows the catalog rule "Respond in the user's language", so a German question gets a German answer without configuration.

## Overriding labels

Pass a partial object. Missing keys keep the built-in string. Provider `chat.labels` applies app-wide; the `labels` prop on `VexaChatOverlay` or `VexaChat` overrides per instance.

```tsx title="app/providers.tsx"
<VexaProvider
  chat={{
    labels: {
      emptyTitle: "Frag einfach",
      emptyDescription: "Stell eine Frage und bekomm die Antwort als UI",
      thinking: "Denkt nach…",
      approve: "Erlauben",
      reject: "Ablehnen",
      placeholder: "Stell eine Frage oder lass dir eine UI bauen...",
      steps: (count) => `${count} Schritte`,
    },
  }}
>
```

## Every key

| Key | Default | Where |
|---|---|---|
| `emptyTitle` | Ask anything. Get UI back. | empty conversation |
| `emptyDescription` | Stream an answer, or generate cards, metrics, and tables in place. | empty conversation |
| `thinking` | Thinking... | streaming indicator |
| `reasoning` | Reasoning | label of each reasoning step inside the steps block, and of a lone Reasoning block that carries no timing |
| `thoughtFor(seconds)` | Thought for `${seconds}` seconds | header of the collapsed steps block and of a lone Reasoning block once streaming ends; the seconds add up every reasoning step |
| `steps(count)` | `${count} steps` | header of the steps block when no reasoning was timed; `thinking` is shown there while the reply streams (not shown when `steps: "hidden"`) |
| `approveTool(tool)` | Approve running `${tool}`? | server or MCP approval card |
| `approved` | Approved | approval card result |
| `rejected` | Rejected | approval card result |
| `approve` | Approve | approval card button |
| `reject` | Reject | approval card button |
| `runOnPage(tool)` | Run `${tool}` on this page? | host tool confirmation |
| `run` | Run | host tool confirmation button |
| `cancel` | Cancel | host tool confirmation button |
| `restore` | Restore | checkpoint link |
| `restoreTooltip` | Restore conversation to this point | checkpoint tooltip |
| `startOver` | Start over | header button aria-label |
| `closeChat` | Close chat | header button aria-label |
| `openAssistant` | Open assistant | launcher aria-label |
| `closeAssistant` | Close assistant | launcher aria-label when open |
| `queued` | Queued | queued messages section |
| `removeQueued` | Remove queued message | queued item button |
| `sentWithAttachments` | Sent with attachments | message text when only files were sent |
| `attachment` | Attachment | queued item without text |
| `securityTitle` | Suspicious text in tool data | injection notice card |
| `securityBody(tool)` | Data returned by `${tool}` contained instructions aimed at the assistant… | injection notice card |
| `buttonPressed(tool)` | the tool name as words (`book_room` → Book room) | a forwarded button press shown as a user message |
| `placeholder` | Ask for an answer or a UI... | composer textarea |
| `send` | Send | send button aria-label |
| `stop` | Stop | send button aria-label while streaming |
| `attach` | Attach | attachment menu button aria-label |
| `addAttachment` | Add photos or files | attachment menu item |
| `takeScreenshot` | Take screenshot | attachment menu item |
| `removeAttachment` | Remove attachment | button on an attached file |
| `selectModel` | Select a model | model picker dialog title |
| `searchModels` | Search models... | model picker search input |
| `noModels` | No models found. | model picker empty state |
| `tokenUsage` | Context usage | token meter aria-label |
| `usageInput` | Input | token meter popover row |
| `usageOutput` | Output | token meter popover row |
| `usageReasoning` | Reasoning | token meter popover row |
| `usageCache` | Cache | token meter popover row |
| `usageTotalCost` | Total cost | token meter popover footer |
| `toolInput` | Parameters | tool call card |
| `toolOutput` | Result | tool call card |
| `toolState(state)` | Pending, Running, Awaiting approval, Responded, Completed, Denied, Error | tool call badge; `state` is the AI SDK `ToolUIPart["state"]` (`ChatToolState`) |
| `usedSources(count)` | Used `${count}` sources | sources block header |

Function-valued keys receive the count, the tool name, or the tool state so the sentence can be built in any word order. `toolState` is the one place a translation needs a map: `toolState: (state) => THAI_STATES[state]` with one entry per `ChatToolState`.

## Hiding composer controls

Strings are not the only thing a host owns in the composer. `chat.composer` (or the `composer` prop on `VexaChat` / `VexaChatOverlay`) switches controls off: `{ attachments: false }` removes the attach menu and ignores dropped or pasted files, `{ tokenUsage: false }` removes the context meter, `{ modelPicker: false }` removes the model button. The model picker already hides itself when only one model is available. See [Provider](/docs/host/provider#chat-defaults).

## Other presentation strings

`title`, `subtitle`, `launcherLabel`, and `suggestions` are separate fields of `chat`, not labels, because they are content rather than chrome. `launcherLabel` falls back to `labels.openAssistant` when unset.

## Model output

Persona text on the server can fix a language for the assistant ("Always answer in German") when the app is single-language. Otherwise leave the catalog rule to follow the user. Currency and number formatting come from `format`, not from labels.
