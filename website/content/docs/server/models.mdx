## Vexa never creates a provider

The library does not import any provider package and never reads an environment variable. `createVexaHandler` requires `model` or a non-empty `models` registry of AI SDK `LanguageModel` instances and throws otherwise. The host owns the provider client, the key, and the env var names, so one deployment can use OpenRouter, another Anthropic, another a mix.

## The registry

```ts title="vexa/server"
type ModelEntry =
  | LanguageModel
  | { model: LanguageModel | (() => LanguageModel); name?: string; provider?: string; maxTokens?: number };

type ModelRegistry = Record<string, ModelEntry>;
```

Keys are the ids the client sends in `body.model`. The first key is the default. `name`, `provider`, and `maxTokens` are metadata for the picker; `provider` is inferred from the id when omitted and `maxTokens` defaults to 128,000.

```ts title="lib/models.ts (mixed providers)"
import { anthropic } from "@ai-sdk/anthropic";
import { openai } from "@ai-sdk/openai";
import type { ModelRegistry } from "vexa/server";

export const models: ModelRegistry = {
  "claude-sonnet-4": { model: anthropic("claude-sonnet-4-20250514"), name: "Claude Sonnet 4", maxTokens: 200_000 },
  "gpt-4.1-mini": { model: openai("gpt-4.1-mini"), name: "GPT-4.1 Mini", maxTokens: 128_000 },
};
```

## Lazy registry

Pass a function so provider construction and env reads happen on the first request, not at import or build time. The function is called once and memoized. Per-entry `model: () => …` is lazy as well, so an unused model never instantiates.

```ts title="examples/shop-admin/lib/models.ts (excerpt)"
import { createOpenAICompatible } from "@ai-sdk/openai-compatible";
import { createGoogleGenerativeAI } from "@ai-sdk/google";
import type { LanguageModel } from "ai";
import type { ModelRegistry } from "vexa/server";

type ModelSpec = { id: string; name: string; maxTokens: number };
type Provider = { create: (id: string) => LanguageModel; models: readonly ModelSpec[]; provider: string };

const QWEN_MODELS: readonly ModelSpec[] = [
  { id: "deepseek-v4-flash-0731", name: "DeepSeek V4 Flash (QwenCloud)", maxTokens: 128_000 },
  { id: "qwen3.8-flash", name: "Qwen 3.8 Flash (QwenCloud)", maxTokens: 128_000 },
];
const GOOGLE_MODELS: readonly ModelSpec[] = [{ id: "gemini-3.1-flash-lite", name: "Gemini 3.1 Flash Lite (AI Studio)", maxTokens: 1_000_000 }];

function qwenProvider(apiKey: string): Provider {
  const client = createOpenAICompatible({ name: "qwencloud", baseURL: "https://maas.qwencloudapi.com/compatible-mode/v1", apiKey });
  return { create: (id) => client(id), models: QWEN_MODELS, provider: "qwen" };
}

function googleProvider(apiKey: string): Provider {
  const client = createGoogleGenerativeAI({ apiKey });
  return { create: (id) => client(id), models: GOOGLE_MODELS, provider: "google" };
}

const PROVIDER_KEYS: ReadonlyArray<[env: string, build: (key: string) => Provider]> = [
  ["QWEN_API_KEY", qwenProvider],
  ["GOOGLE_GENERATIVE_AI_API_KEY", googleProvider],
];

/** Every provider whose key is set, in order; the first entry (DeepSeek V4 Flash via QwenCloud) is the default model. */
export function demoModels(): ModelRegistry {
  const providers = PROVIDER_KEYS.flatMap(([env, build]) => (process.env[env] ? [build(process.env[env] as string)] : []));
  if (providers.length === 0) throw new Error("Set QWEN_API_KEY or GOOGLE_GENERATIVE_AI_API_KEY in examples/shop-admin/.env.local");
  return Object.fromEntries(
    providers.flatMap(({ create, models, provider }) =>
      models.map(({ id, name, maxTokens }) => [id, { model: () => create(id), name, provider, maxTokens }]),
    ),
  );
}
```

The shipped file also knows DeepSeek's own API, Groq, Anthropic and OpenRouter; whichever keys exist appear in the picker next to the mock, and `VEXA_PROVIDERS=GOOGLE_GENERATIVE_AI_API_KEY,QWEN_API_KEY` reorders them. DeepSeek V4 Flash is the default because it scored best on the data-checked generative-UI eval (`bun run eval:ui`, `docs/admin-ui-eval.md`); QwenCloud models get `providerOptions: { qwencloud: { enable_thinking: false } }` so they answer in 10–15 s instead of a minute.

```ts title="app/api/chat/route.ts"
export const { GET, POST } = createVexaHandler({
  models: demoModels,
  providerOptions: { openrouter: { reasoning: { effort: "medium" } } },
});
```

## Per-request resolver

`model` can be a function `(body, req) => LanguageModel | undefined`. It sees the parsed body and the `Request`, so a host can choose a provider or an API key from a session cookie or a tenant header. Returning `undefined` yields `400 No model available for this request`.

```ts title="tenant keys"
export const { POST } = createVexaHandler({
  model: async (body, req) => {
    const tenant = await tenantFrom(req.headers.get("cookie"));
    if (!tenant) return undefined;
    return createAnthropic({ apiKey: tenant.anthropicKey })("claude-sonnet-4-20250514");
  },
});
```

With a resolver, `body.model` is yours to interpret; the handler does not check it against a registry, and `GET` returns an empty list.

## Resolution order

| Config | `body.model` | Result |
|---|---|---|
| `model` is a resolver | passed to the resolver | whatever it returns |
| `model` is a `LanguageModel` | ignored | that model |
| `models` registry | id in registry | that entry |
| `models` registry | missing or empty | first key |
| `models` registry | unknown id | `400` |
